フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストは、すべて 1 つのブランチに保存されています。まとめてレビューし、プルリクエストを作成しましょう。星評価のプルリクエスト (PR) は自分でマージしました。今回は **Agent Merge** にマージのプロセスを任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。このワークショップでは手順を簡潔にするため、フィルター機能と品質ワークフローを 1 つのセッションとブランチにまとめ、そのすべてを 1 つの PR に含めています。

このレッスンでは、次のことを行います。

- Agent Merge と、マージまでのライフサイクルを自動化する仕組みを学びます。
- 機能全体の PR と検証の証拠を確認します。
- レビュー後にのみ Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルター機能の開発を通じて、Copilot を使って機能を計画、実装、検証してきました。Tailspin Toys は、マージの許可を開発者の管理下に置いたまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするために必要な残りの作業を自動化します。有効にすると、セッションのアプリが PR を読み取り、CI チェックの失敗の修正、レビューコメントへの対応、必要に応じたリベースなど、マージを妨げている問題を解決します。その後、GitHub が許可した時点で PR をマージします。バックグラウンドで実行され、アプリの再起動後も動作を継続し、PR がマージされると自動的に無効になります。

これまでは **Merge pull request** を自分で選択していました。Agent Merge にその作業を任せることはできますが、コードの編集とマージには引き続き明示的な許可が必要です。許可する操作と作業内容を確認してから、マージ権限を与えてください。

## Agent Merge で PR を管理する

コードの作成とレビューが完了したら、Agent Merge に PR のプロセスを任せます。

1. エージェントの選択欄で **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンの項目を選択しただけでは開始されません。

Agent Merge が開始され、次の作業を行います。

- タイトルと説明を付けてプルリクエストを作成します。
- Issue からセッションを開始した場合は、関連する Issue を PR 本文で参照します。
- ターゲットブランチに対してリベースを行うか、マージ競合を処理します。
- CI を監視し、すべてのチェックに合格するよう対応します。
- 他の開発者や Copilot code review からのフィードバックを監視し、コメントを解決するために変更を加えます。
- すべての条件が満たされた後、PR を自動的にマージすることもできます。

すべての条件が満たされたら、Agent Merge に PR のマージも任せましょう。

5. マージを許可する前に、PR の diff と検証の証拠を確認します。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックマークがあることを確認します。
8. 次のように、マージを明示的に依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進行状況を確認し、報告されたブロッカーに対処します。次に進む前に、PR のステータスが **Merged** になっていることを確認してください。マージ権限が有効になっていることや、エージェントが実行中であることだけでは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリ保護ルールや権限不足を回避しません。続行する前に、そのようなブロッカーを解決してください。
