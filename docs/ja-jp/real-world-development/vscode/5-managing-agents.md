GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分を確認し、個々の変更を採用または却下し、エディターを離れずに追加のプロンプトを送って作業を調整したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッションの途中でエージェントに指示し、ハイコントラストモードと合わせてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードへの切り替えも追加してほしいとのことです。新しい会話を最初から始めずに、既存のセッションに指示を加えて作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調べたファイル、実行したコマンド、提案した編集などを確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取りと編集、実行許可を求めるターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を取り消し、エージェントに再度作業させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライトモードを追加してもらう

ハイコントラストモードができたので、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けるため、エージェントは直前の作業、変更したコンポーネント、スタイルの方針、local storage を使う方法を引き継ぎます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは前の変更を確認してからライトモードを追加します。
3. ハイコントラストモードの場合と同様に、新しい編集を確認し、各差分で **Keep** または **Undo** を選びます。
4. エージェントが意図と異なる方向に進んだ場合 (たとえば、気に入らない方法でトグル UI をリファクタリングしようとした場合) は、チャット入力欄の隣にある **Stop** を選択して停止し、追加の説明を送ります。

> [!TIP]
> 進行中のセッションに指示を加えると、最初からやり直すよりも速く調整できます。追加プロンプトで修正を依頼したり (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、方針を修正したり (「3つ目のトグルは追加せず、既存の設定パネルにライトモードを統合する」)、範囲を広げたり (「両方のトグルにキーボードショートカットも追加する」) できます。

## 変更されたファイルを確認する

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **ソース管理**ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティの方法 (ARIA 属性、キーボード操作、セマンティック HTML、local storage への保存) が反映されていることを確認します。
4. 内容に問題がなければ、ソース管理パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中のセッションを監視して方向付けしました。ファイルの編集を確認して採用または却下し、コンテキストを保ったまま追加プロンプトを送り、作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または却下しました。
- 追加プロンプトを使って、進行中のセッションに指示しました。
